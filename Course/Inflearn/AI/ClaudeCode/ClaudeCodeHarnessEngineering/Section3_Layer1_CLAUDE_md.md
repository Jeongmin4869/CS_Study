# CLAUDE.md - 4가지 행동 원칙

LLM 코딩 어시스턴트의 대표적인 문제

* 잘못된 가정
* 과도한 복잡성
* 요청 범위를 벗어난 코드 수정

→ **더 좋은 모델보다 더 나은 지시가 먼저다.**

CLAUDE.md에 행동 원칙을 정의하여 이러한 문제를 줄일 수 있다.

---

# 원칙 1. 먼저 생각하기

> 코딩하기 전에 먼저 생각하라.

요청을 받았을 때 바로 코드를 작성하지 않고, **가정과 불확실성을 먼저 확인**한다.

* 요청을 어떻게 이해했는지 명시
* 모호한 경우 옵션을 제시하고 확인
* 더 나은 방법이 있다면 먼저 제안
* 이해되지 않는 부분은 질문하고 멈추기

---

# 원칙 2. 단순함 우선

> 문제를 해결하는 데 필요한 최소한의 코드만 작성한다.

요청하지 않은 기능이나 과도한 설계를 추가하지 않는다.

* 요청 범위 밖의 기능 추가 금지
* 불필요한 추상화 금지
* "나중을 위해" 유연성 추가 금지
* 실제 발생하지 않는 시나리오에 대한 과도한 방어적 처리 금지
* 더 단순하게 해결할 수 있다면 단순화

---

# 원칙 3. 최소 개입

> 꼭 필요한 것만 건드려라.

변경하는 모든 코드는 **사용자의 요청과 직접 연결**되어야 한다.

* 요청한 부분만 수정
* 기존 코드 스타일 유지
* 인접 코드·주석·포맷 임의 수정 금지
* 정상적으로 동작하는 코드의 불필요한 리팩토링 금지
* 관련 없는 레거시는 삭제하지 않고 언급만

### 내가 만든 변경으로 생긴 불필요한 코드

* 불필요해진 import 제거
* 더 이상 사용하지 않는 함수 삭제

→ **원래 존재하던 레거시는 요청 없이 삭제하지 않는다.**

---

# 원칙 4. 목표 기반 실행

> 성공 기준을 정의하고 그때까지 반복하라.

"어떻게 할 것인가"보다 **"무엇이 달성되어야 하는가"**&#xB97C; 정의한다.

### 명령형

```text
"유효성 검사 추가해줘"
```

### 목표 기반

```text
"잘못된 입력에 대한 테스트를 작성하고,
그 테스트가 통과하도록 만들어줘"
```

### 멀티스텝 작업

```text
1. [단계 설명] → 검증: [완료 기준]
2. [단계 설명] → 검증: [완료 기준]
3. [단계 설명] → 검증: [완료 기준]
```

명확한 성공 기준이 있으면 LLM이 결과를 확인하며 반복해서 작업할 수 있다.

---

# 4가지 원칙 정리

```text
원칙 1. 먼저 생각하기
→ 가정을 드러내고 모호함을 해소한다.

원칙 2. 단순함 우선
→ 필요한 최소한의 코드만 작성한다.

원칙 3. 최소 개입
→ 요청과 직접 연결된 부분만 변경한다.

원칙 4. 목표 기반 실행
→ 검증 가능한 목표를 정의하고 달성될 때까지 반복한다.
```
