# Claude Code의 4개 레이어

Claude Code는 크게 **Context → Composition → Control → Capability**의 4개 레이어로 구성된다.

이 4개의 레이어는 서로 독립적으로 동작하는 것이 아니라, **서로 연결되어 Claude Code의 개발 역량을 확장한다.**

---

## 1. Context — 프로젝트의 장기 기억

프로젝트에 필요한 정보와 코드베이스를 이해하고, 작업에 필요한 컨텍스트를 유지하는 레이어

### 1.1 CLAUDE.md — 영속적인 프로젝트 메모리

레포지토리 루트에 위치하는 Markdown 파일.

프로젝트에서 필요한 다음과 같은 정보를 저장한다.

* 코딩 컨벤션
* 아키텍처 결정
* 프로젝트 구조
* 팀 개발 규칙
* 테스트 정책
* 금지된 패턴

Claude가 세션마다 `CLAUDE.md`를 참고하기 때문에 프로젝트의 규칙과 맥락을 지속적으로 유지할 수 있다.

### 1.2 `/init`

기존 코드베이스를 분석하여 `CLAUDE.md` 작성을 돕는다.

* 프로젝트 구조 분석
* 핵심 파일 파악
* 의존성 분석
* 코드베이스의 주요 특징 파악

기존 프로젝트에서도 Claude가 빠르게 작업할 수 있는 컨텍스트를 구성할 수 있다.

### 1.3 에이전틱 코드 탐색

단순한 키워드 검색을 넘어 **코드의 의미와 관계를 파악하며 코드베이스를 탐색**한다.

자연어로 원하는 코드를 설명하면 관련 파일과 구현을 찾아가며 작업할 수 있다.

---

# 2. Composition — 팀의 역량을 쌓기

반복되는 작업과 전문 지식을 **재사용 가능한 형태로 구성하는 레이어**

### 2.1 Custom Slash Commands

팀에서 반복적으로 사용하는 프롬프트를 명령어로 정의한다.

예:

```text
/review
/dp-check
```

반복 작업을 한 줄의 명령어로 실행할 수 있으며, 팀의 베스트 프랙티스를 코드처럼 버전 관리할 수 있다.

### 2.2 Skills

`SKILL.md`를 통해 특정 작업에 필요한 전문 지식을 정의한다.

예:

* Kubernetes 전문가
* 보안 리뷰어
* DB 최적화 전문가
* 특정 프로젝트의 도메인 전문가

Claude가 작업 상황에 맞는 Skill을 선택하여 필요한 지식과 작업 방법을 활용할 수 있다.

### 2.3 Subagents

복잡한 작업을 여러 전문 작업으로 나누어 위임한다. (병렬적) 

예:

* 테스트 작성
* 코드 리뷰
* 문서화
* 리팩토링

각 작업을 별도의 Subagent에게 맡겨 복잡한 작업을 효율적으로 처리할 수 있다.

### 2.4 Plugins

Skills, Commands 등의 기능을 하나의 패키지로 구성하여 쉽게 설치하고 공유할 수 있다.

팀에서 자주 사용하는 개발 환경과 작업 방식을 하나의 플러그인으로 패키징하여 배포할 수 있다.

---

# 3. Control — 실행 전 검토와 자동화

Claude가 **어떻게 행동할지 통제하고, 실행 과정에 안전장치를 추가하는 레이어**

### 3.1 Plan Mode

코드를 실제로 수정하기 전에 작업 계획을 먼저 검토한다.

```text
Plan
 ↓
계획 검토
 ↓
승인 / 수정
 ↓
Code
```

큰 리팩토링이나 파일 삭제 등 영향 범위가 큰 작업에서 활용할 수 있다.

### 3.2 Hooks

도구 실행 전후에 자동으로 동작하는 가드레일이다.

#### PreToolUse

도구 실행 전에 동작한다.

* 위험한 명령 차단
* 실행 전 검증
* 로깅
* 특정 작업에 대한 승인 절차

#### PostToolUse

도구 실행 후에 동작한다.

* 테스트 자동 실행
* 린터 검사
* 결과 검증
* 알림

Claude의 행동에 자동화된 안전장치를 추가할 수 있다.

### 3.3 Headless Mode

인터랙티브한 CLI 화면 없이 Claude를 명령어 형태로 실행한다.

```bash
claude -p "PR 설명 작성해줘"
```

CI/CD나 자동화 스크립트, cron 등의 환경에 Claude를 통합할 수 있다.

# 4. Capability — 외부 세계와 연결

Claude의 기능을 외부 시스템과 연결하여 **실제로 개발 환경과 상호작용할 수 있도록 확장하는 레이어**

### 4.1 MCP Server

MCP를 이용하여 외부 시스템과 Claude를 연결한다.

예:

* Jira
* PostgreSQL
* GitHub
* Linear
* Slack

예를 들어 다음과 같은 작업을 자연어로 요청할 수 있다.

```text
이 이슈를 Jira에 생성하고
관련된 코드를 찾아줘.
```

Claude가 외부 시스템의 데이터와 개발 환경을 함께 활용할 수 있다.

### 4.2 이미지 → 코드

이미지나 화면을 분석하여 코드 구현에 활용할 수 있다.

예:

* UI 디자인 → 코드
* 스크린샷 → 컴포넌트
* 다이어그램 → 구현 구조

### 4.3 Git 자연어 Workflow

Git 작업을 자연어로 요청하여 개발 workflow에 활용할 수 있다.

예:

```text
변경사항을 확인하고 적절한 커밋 메시지로 커밋해줘.
```

# Claude Code의 전체 Workflow

4개의 레이어를 실제 개발 workflow에 연결하면 다음과 같은 흐름을 만들 수 있다.

```text
PLAN
계획 수립 및 검토
   ↓
CODE
Context를 기반으로 코드 작성
   ↓
TEST
테스트 및 자동 검증
   ↓
COMMIT
Git 자연어 Workflow
   ↓
PR
GitHub Pull Request 생성
```

각 단계에서 4개의 레이어가 서로 연결된다.

```text
Context
   ↓
프로젝트 이해
   ↓
Composition
   ↓
작업 능력 확장
   ↓
Control
   ↓
실행 과정 통제 및 자동화
   ↓
Capability
   ↓
외부 시스템과 연결
```

---

# 핵심

4개의 레이어는 각각 독립적인 기능이 아니라 서로 연결되어 Claude Code의 개발 workflow를 구성한다.

> **Context**가 프로젝트를 이해하고
> **Composition**이 필요한 역량을 구성하고
> **Control**이 실행을 통제하고
> **Capability**가 외부 세계와 연결한다.

이 4개의 레이어가 연결되면 Claude Code는 단순한 **코드 생성 도구를 넘어**, 프로젝트를 이해하고 계획을 세우며 코드를 작성하고 테스트하고 Git workflow까지 수행하는 **에이전틱 개발 런타임**으로 확장될 수 있다.
