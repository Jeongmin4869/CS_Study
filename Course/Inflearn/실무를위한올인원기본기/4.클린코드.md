## 03 - 함수
      
### 01) 함수의 역할은 하나만 할 수 있도록 한다 (SRP)
- 함수의 역할이 많아지면 오류가 날 가능성이 커지며 가독성이 떨어진다.
- 함수에 대한 테스트를 진행하기 어려워진다. 
   
as-is
``` python 
def create_user(email, password):
    # validation 로직
    if "@" not in email or len(password) < 6 :
        raise Exception("유저 정보를 제대로 입력하세요")

    user = {"email" : email, "password" : password}
    
    database = Database("mysql")
    database.add(user)
    
    email_client = EmailClient()
    email_client.set_config(...)
    email_client.send(email, "회원가입을 축하합니다")

    return True

   
```
   
to-be
``` python 
def create_user(email, password):
    validate_create_user(email, password)

    user = build_user(email, password)
    
    save_user(user)
    send_email(email)
    return

def validate_create_user(email, password):
    if "@" not in email or len(password) < 6 :
        raise Exception("유저 정보를 제대로 입력하세요")

def build_user(email, password):
    return {
        "email": email,
        "password": password
    }

def save_user(user):
    database = Database("mysql")
    database.add(user)

def send_email(email):
    email_client = EmailClient()
    email_client.set_config(...)
    email_client.send(email, "회원가입을 축하합니다")

```

as-is
``` python 
def create_user(email, password):
    # validation 로직
    if "@" not in email or len(password) < 6 :
        raise Exception("유저 정보를 제대로 입력하세요")

    ...

def update_user(email, password):
    # validation 로직
    if "@" not in email or len(password) < 6 :
        raise Exception("유저 정보를 제대로 입력하세요")
    
```
   
to-be
``` python 

def validate_create_user(email, password):
    if "@" not in email or len(password) < 6 :
        raise Exception("유저 정보를 제대로 입력하세요")

def create_user(email, password):
    validate_create_user(email, password)
    ...

def update_user(email, password):
    validate_create_user(email, password)
    ...

```

### 04) 사이드 이팩트를 잘 핸들링한다.
- 사이드 이팩트는 함수가 실행됐을 때 함수 외의 다른 것들에 영향을 주는 것을 의미한다.
- 사이드 이펙트를 잘 다루지 못하면 예상치못한 문제들이 발생할 수 있다. 
   
```python 
#사이드 이펙트가 없습니다.
def get_user_instance(email, password):
    user = User(email, password)
    return user
	
#사이드 이펙트가 있습니다
def update_user_instance(user): 
    user.email = "new email" #인자로 받은 user 객체를 업데이트합니다.
    ...

#사이드 이펙트가 있습니다
def create_user(email, password):
    user = User(email, password)
    start_db_session() #외부의 DB Session에 변화를 줄 수 있습니다. 
    ...

```
   
### 사이드 이펙트 핸들링
- 1. 코드를 통해 충분히 기능을 예측할 수 있도록 네이밍한다.
  - Update, set 같은 직관적인 preifx를 붙여 사이드 이펙트가 있을 수 있음을 명시한다. 
- 2. 함수의 사이드 이펙트가 있는 부분과 없는 부분으로 잘 나눠 관리한다.
   - 명령(side effect O)과 조회(side effect X)를 분리하는 CQRS 방식이 있다.
- 3. update문을 남발하기 보다는 순수 함수 형태로 사용하는 것이 더 직관적이며 에러를 방지할 수 있다.
   
as-is
```python
carts = []

#사이드 이펙트를 발생시킴
def add_cart(product):
    carts.append(product)

product = Product(...)
add_cart(product)

```
   
to-be
```python
carts = []

#사이드 이펙트가 없는 순수함수
def get_added_cart(product):
    return [...carts, prodcut]

product = Product(...)
carts = get_added_cart(product)

```
