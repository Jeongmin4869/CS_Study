# 1. 프로세스와 스레드 기본
   
## 01) 프로세스 
   
<img width="2991" height="1588" alt="Image" src="https://github.com/user-attachments/assets/4af2529c-39a5-4e4a-bd01-ac1e5a2c4c23" />
   
- 프로세스는 운영체에 위에 실행되고 있는 프로그램을 뜻한다.
- 유저가 프로그램을 실행했다면, 프로세스는 메모리 위에 올라가 있게 되며, 운영체제에 의해 CPU, 메모리 자원을 할당받게 된다.
- 프로세스는 독립된 메모리 영역으로 Code, Data, Stack, Heap을 할당받는다.
  - Code : 개발자가 작성한 코드
  - Data : 전역변수, 정적변수, 배열, 구조체 등 프로그램이 실행되면서 생기는 정적인 데이터들이 저장됨
  - Stack : 함수 호출과 관련된 정보(실행정보, 지역변수, 파라미터 등)이 저장된다. 일반저긍로 컴파일 타임에 Stack의 크기가 결정된다.
  - Heap : 런타임에 동적으로 메모리를 처리해야하는 상황에서 사용되는 공간  Array를 사용하거나 외부 파일을 읽을 때 등을 예로 들 수 있다,     사용자에 의해 메모리 공간이 동적으로 할당되고 해제될 수 있다.   
   
#### Stack Overflow
- 프로세스에 할당된 Stack 메모리가 초과했을 대 생기는 문제.
- 함수에 너무 큰 지역변수를 선언하거나 재귀적으로 무한정으로 함수를 호출하게 될 때 발생
- 주로 런타임 도중에 발생. 
   
   
## 02) 스레드
   
<img width="1112" height="506" alt="Image" src="https://github.com/user-attachments/assets/6bf3c456-6b09-401c-b002-6b88ed8495ee" />
   
- 스레드는 프로그램의 작업을 수행하는 역할을 한다. 일반적으로 프로세스 안에서 실제 코드를 실행하는 단위를 뜻한다. 
  - 스레드는 CPU의 기본 이용 단위이다. 한개의 스레드 작업은 1개의 CPU코어에 할당되게 된다.
  - 스레드가 실행되기 위해선 자원(함수 실행 정보, 지연변수 등)을 저장할 메모리가 필요하며, 이는 프로세스가 할당받은 메모리를 사용한다. 
- 스레드는 프로세스 내에 존재하기 때문에 프로세스의 자원을 공유한다. 각자의 스레드는 Stack을 별도로 가지고 있게 되며 나버지 자원(Heap, Code, Data)를 공유하게 된다.
  - 만약 여러 스레드가 실행된다면 프로세스의 자원을 공유하기에 따르게 자원을 가져다 쓸 수 있다.
  - 반면 스레드가 아닌 다른 프로세스를 사용하기 위해서는 IPC(Inter-Process-Communication)라는 방식을 사용해야 한다. 
- 보통 개발한 프로그램을 실행하면 일반적으로 1개의 프로세스와 1개의 메인 스레드를 가지게 된다.
- 그러나 프로그램이 해야 할 테스트가 많아지면 자연스럽게 여러 개의 스레드를 동시에 실행할 수 있으며, 혹은 여러 개의 프로세스를 동시에 운영할 수도 있다.

# 2. 병렬성과 동시성 
   
## 01) 동시성
   
<img width="701" height="216" alt="Image" src="https://github.com/user-attachments/assets/fa002761-6b17-4076-b2ef-089c1ee403d3" />
   
### 배경
- 컴퓨터의 구성요소 중 하나인 CPU(Central Processing Unit)는 말 그대로 컴퓨터의 중심부에서 컴퓨터 명령을 처리하는 역할을 한다.
- 우리가 컴퓨터를 사용하며 내리는 명령들은 CPU가 처리하게 된다.
- 컴퓨터 발전 초기 컴퓨터 하나당 CPU는 하나였으며, CPU는 하나이니 한번에 처리할 수 있는 명령도 하나였다.
   
### 개념
- 하나의 CPU를 최대한 활용하여 여러 작업을 빠르게 수행하도록 한다.
- 여전히 CPU는 한번에 하나의 명령어만 처리하지만, CPU가 맡는 ㅍ로세스(스레드)가 Block 상태가 되면 빠르게 다음에 처리해야할 프로세스가 CPU를 점유하게 된다.
- CPU입장에서는 여러 프로세스를 번갈아가며 일하기 위해 프로세스의 정보들을 메모리에 저장하고 불러와야하며, 이 때 CPU가 작업애햐 할 프로세스를 바꾸는 일을 ***컨텍스트 스위칭*** 이라고 한다. 
- CPU가 프로세스의 명령어를 동시에 처리하는 것처럼 느끼게 하는 현상을 동시성(Concurrency)라고 한다. 
   
- 동시성이라는 개념은 물리적으로 CPU1개의 코어에서만 동작하는 개념은 아니다.
- 제한된 자원에서 여러 작업을 한번에 실행시키려는 논리적인 개념이다. 
   
### CPU Bound vs I/O Bound
- 컴퓨터가 수행하는 하나의 작업은 CPU와 I/O(input Output) 작업으로 이루어진다.
- 이 때 컴퓨터 작업은 크게 CPU Bounded Task, I/O Bounded Task로 2개로 나누어진다.
- CPU Bounded Task
   - 작업을 실행하는데 CPU를더 많이 쓰는 작업을 말한다.
   - 머신러닝과 같이 연산 작업이 복잡한 로직이 여기에 해당한다.
- I/O Bounded Task
   - 작업을 실행하는데 CPU보다 I/O가 더 많은 작업을 말한다.
   - 크롤링 로직, DB와 연결하여 데이터를 주고받는 로직 등이 여기에 해당한다.
   - 웹, WAS서버는 I/O Bounded한 경우가 많다. 
   
   
## 02) 병렬성
      
<img width="700" height="391" alt="Image" src="https://github.com/user-attachments/assets/ac88e89d-de66-4f6d-af3e-67442cbc8c58" />
   
- 컴퓨터 하드웨어는 점점 발전하여 컴퓨터 하나당 2개 이상의 CPU를 가질 수 있게 되었다.
- CPU가 2개이므로 이제 동시에 2개의 명령어를 실행할 수 있다.
- 여러개의 작업이 동시에 진행되는 현상을 병렬성(Paralleism)이라고 부르다.
- “동시성”은 실제로는 하나의 명령을 빠르게 수행하지만 처리속도가 매우 빨라 여러 작업이 동시에 진행되는것처럼 느껴지게 해주었다.
- “병렬성”은 실제로 여러 개의 명령어를 동시에 실행하는 것이다. 운영체제가 여러 CPU를 골고루 쓰도록 매니징해준다. 
   
<img width="700" height="491" alt="Image" src="https://github.com/user-attachments/assets/a90b1504-857f-499e-95e2-c47b9b0870ba" />   
   
- 병렬성은 동시성을 품을수도 있다. 여러개의 CPU를 사용하면서 각각의 CPU에서 여러 테스크(스레드나 프로세스)를 실행시키려고 한다면 동시성을 구현한 것이다.
   
   
## 03) 정리
   
- 동시성은 하나의 CPU로 여러 작업을 빠르게 처리하는 것이다. 
   - 여러개의 작업이 한번에 실행되는 것처럼 보이지만, 실제로는 하나의 CPU에서 처리하고 있는 것이다.
   - CPU1코어에 해당하는 물리적인 개념이 아닌, 제한된 자원에서 여러 작업을 한번에 실행시키려는 논리적인 개념이다. 
- 병렬성은 여러개의 CPU로 여러 작업을 빠르게 처리하는 것이다.
   - 여러 작업이 실제로 여러개의 CPU를 통해 한번에 처리된다.
